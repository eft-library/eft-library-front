# 데스크톱 V3 웹 연동

백엔드의 `where_am_i_desktop_v3_backend.ko.md`를 기준으로 개인 위치 WebSocket의 레이드 타이머를 연결한다. 버전 확인·맵 별칭·경로 수집은 데스크톱 측 기능이며 웹에서 중복 호출하지 않는다.

## 동작

- `wpf_raid_state.payload`의 nullable `session_id`, `timer_observed_at`, `raid_ends_at`을 수신한다. 기존 프로그램의 필드 생략도 허용한다.
- 활성 상태, 현재 지도 일치, 세션·시작 시각·타이머가 유효할 때 종료 예정 UTC 시각에서 브라우저 현재 시각을 빼서 계산한다. 전송 지연·재연결·새로고침 때 전체 길이를 다시 시작하지 않는다.
- 화면 상단에 자동 잔여 시간을 표시한다. BTR 자동 예상 계산은 Woods부터 사용하며 다른 BTR 지도는 기존 수동 입력을 유지한다.
- 타이머가 없거나 null이면 자동 기준을 비운다. 지도 기본 레이드 길이나 35분 같은 값을 자동 종료 시각으로 만들지 않는다.
- 수동으로 시작한 타이머는 자동보다 우선한다. 프로그램 타이머가 있으면 전환 버튼으로 돌아갈 수 있다. 백엔드 전달 문서의 수동 입력 유지 요구에 따라 같은 지도에서 새 세션·null 스냅샷이 와도 사용자가 선택한 수동 입력을 덮어쓰지 않는다. 지도·계정이 바뀌면 실행 중인 수동 타이머를 정리한다.
- 새 세션·지도·시작 시각이나 비활성 상태에서는 이전 위치를 정리한다. null 스냅샷을 이전 타이머에 병합하지 않는다.
- 기존 정적 JSON에 BTR 필드가 없으면 동일한 V3 지도 상세 API에서 해당 노선 필드만 보완한다. 실패해도 지도 자체는 계속 사용할 수 있다.

## 배포와 확인

백엔드의 새 필드 전달과 타이머 캐시를 배포한 뒤, 새 프로그램과 웹을 적용한다. 새 필드가 없는 서버·프로그램에서는 자동 타이머가 생기지 않고 수동 입력이 유지된다.

브라우저·게임 PC·서버의 시계 오차는 실제 Woods 게임 잔여 시간과 비교해야 한다. 임의 시계 보정은 넣지 않는다. BTR은 예상 운행·정차 정보이며 실제 도착 감지나 레이드 종료 판정으로 설명하지 않는다.

검증 스크립트:

- `script/check-desktop-raid-timer.cjs`: 지연·재연결·만료, 맵·세션·null·구버전 및 잘못된 필드.
- `script/check-desktop-raid-timer-browser.cjs`: Woods 자동 타이머, 60초 이후 재연결·새로고침, 수동 우선·자동 복귀, 상태 교체와 위치 정리, 모바일·라이트·다크 모드.
- 기존 위치 수신·파티 회귀 테스트도 함께 실행한다. 프로그램 쓰기 이벤트는 모사하며 실제 운영 사용자에게 레이드 상태를 전송하지 않는다.
